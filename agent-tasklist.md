# agent-tasklist.md

# Filmoteka — Agent Tasklist

> Цель: вести разработку проекта filmoteka через агента пошагово, от инициализации до полнофункциональной домашней видеотеки.
>
> Общие правила для агента:
> - Брать **одну задачу за итерацию**.
> - До начала реализации коротко описывать план.
> - После завершения задачи перечислять изменённые файлы.
> - После каждой задачи запускать релевантные проверки.
> - Не делать большие несогласованные рефакторы.
> - Если задача меняет поведение системы, нужно добавить или обновить тесты.
> - После каждой завершённой задачи обновлять `docs/progress.md`.

---

## Статусы

- `[ ]` — не начата
- `[~]` — в работе
- `[x]` — выполнена
- `[!]` — заблокирована

## 3.11. Bugfixes

- [x] **BUGFIX-002** Починить 500 на MKV с русским названием.

  Проблема: `Content-Disposition` заголовок в `_ffmpeg_remux_stream()` содержит `path.stem` с кириллицей напрямую, но HTTP-заголовки обязаны быть в latin-1. Решение: заменить на `filename*=UTF-8''...` (RFC 5987).

  2. MP4 с кириллическим названием продолжает работать.

Решение: добавить `TMDB_API_KEY: ${TMDB_API_KEY}` в секцию `environment` сервисов api и worker. Docker Compose прочитает значение из `.env` автоматически.

  Проблема: `urllib.request.urlopen()` возвращает `[Errno 111] Connection refused` при попытке доступа к `api.themoviedb.org` из контейнера. DNS работает, но TCP-соединение отклоняется.

# 5. V3 — DeepSeek Integration

> DeepSeek как внешняя нейросеть для enrichment метаданных при импорте
> и для mood-based рекомендаций.

## 5.1. DeepSeek enrichment + recommendations

- [x] **V3-001** Интегрировать DeepSeek API для enrichment метаданных при импорте.

  Проблема: сейчас импорт парсит только имя файла (title, year) и берёт постер из OMDB.
  Жанры, описание, актёры, страна остаются пустыми.

  Решение: при импорте (или по отдельной admin-кнопке) отправлять название фильма
  в DeepSeek, получать structured ответ с полями: genre, description, actors, country,
  year. Сохранять в Film с source="deepseek" и confidence=0.9.

  Требования:
  - `DEEPSEEK_API_KEY` в `.env` (опционально; без ключа — текущее поведение)
  - graceful degradation: если ключа нет или API недоступен — импорт не ломается
  - DeepSeek API endpoint: `https://api.deepseek.com/v1/chat/completions`
  - structured output через prompt engineering (JSON schema в system prompt)
  - флаг `needs_review` для записей, где confidence < порога

  Проверка результата:
  1. С DeepSeek API ключом: у новых фильмов появляются жанры, описание, актёры, страна.
  2. Без ключа: импорт работает как раньше, enrichment пропускается.
  3. При таймауте/ошибке DeepSeek: импорт завершается, ошибка логируется.
  4. Metadata source фиксируется как "deepseek".

- [x] **V3-002** Подключить DeepSeek к рекомендациям по настроению.

  Заменить/дополнить текущий hardcoded `llama3.2` в `_llm_mood_recommendations()`
  на DeepSeek, когда `DEEPSEEK_API_KEY` задан. Оставить `LLM_API_URL` как fallback
  для локальных моделей (Ollama).

  Порядок выбора LLM:
  1. Если есть `DEEPSEEK_API_KEY` → использовать DeepSeek
  2. Если есть `LLM_API_URL` → использовать локальную модель (как сейчас)
  3. Иначе → keyword fallback

  Проверка результата:
  1. С `DEEPSEEK_API_KEY` — рекомендации используют DeepSeek.
  2. С `LLM_API_URL` (без `DEEPSEEK_API_KEY`) — работает как сейчас.
  3. Без обоих — keyword fallback.

- [x] **V3-003** Добавить алиасы для имён файлов через LLM.

  Проблема: в интерфейсе и поиске используются «сырые» имена файлов
  (например `Брат.1997.WEB-DLRip-AVC_[New-team]_by_AVP_Studio.mkv`).
  Это нечитаемо для пользователя и плохо ищется.

  Решение:
  - Новая колонка `media_alias` в `media_files` (VARCHAR, default = filename).
  - LLM (DeepSeek или опционально локальная) парсит filename в человекочитаемый
    алиас: «Брат (1997)».
  - Алиас хранится в БД, сервис использует его вместо filename для отображения
    и поиска.
  - Если LLM недоступен или ошибка — алиас остаётся равным filename (graceful).

  Admin UI:
  - Две кнопки на admin-странице:
    1. **"Generate aliases (defaults only)"** — проходит только записи, где
       `media_alias` до сих пор равен filename (никогда не обрабатывались).
    2. **"Re-generate all aliases"** — проходит всю базу заново, перезаписывает
       алиасы.
  - Обе — через background job (202 Accepted + polling), как остальные admin
    операции.
  - Прогресс: сколько обработано / ошибок / пропущено.

  Проверка результата:
  1. После Generate aliases: у файлов с дефолтным алиасом появляется
     человекочитаемое имя.
  2. Re-generate all: перезаписывает даже уже установленные алиасы.
  3. Без `DEEPSEEK_API_KEY` и `LLM_API_URL`: алиасы остаются filename,
     кнопки показывают сообщение «LLM not configured».
  4. Поиск по алиасу находит фильм.

- [ ] **V3-004** Добавить frontend-кнопки для DeepSeek enrichment в админку.

  Проблема: `POST /admin/enrich/deepseek` и `/enrich/deepseek/all` существуют
